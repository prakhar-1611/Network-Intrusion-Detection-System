# \# Network Intrusion Detection System — CIC-IDS-2017

# 

# An ML-based NIDS that classifies real network flow data into BENIGN vs.

# attack types (DDoS, PortScan, Brute Force, Web Attacks, Botnet,

# Infiltration, DoS variants), with per-alert explainability and a small

# SOC-style dashboard. Built on the CIC-IDS-2017 dataset from the

# Canadian Institute for Cybersecurity.

# 

# \## Pipeline

# 

# ```mermaid

# flowchart TD

# &#x20;   A\[Raw CIC-IDS-2017 CSVs<br/>8 files, \~2.8M rows] --> B\[preprocess.py]

# &#x20;   B --> C\[Drop leaky columns<br/>IP, timestamp]

# &#x20;   C --> D\[Drop NaN/Inf rows<br/>remove duplicates]

# &#x20;   D --> E\[Clean parquet<br/>data/processed/]

# &#x20;   E --> F\[train.py]

# &#x20;   F --> G{Model choice}

# &#x20;   G -->|rf| H\[Random Forest<br/>300 trees, balanced weights]

# &#x20;   G -->|xgb| I\[XGBoost<br/>400 rounds, sample weights]

# &#x20;   H --> J\[Saved model + test split<br/>models/]

# &#x20;   I --> J

# &#x20;   J --> K\[evaluate.py]

# &#x20;   K --> L\[Precision/Recall/F1 per class<br/>confusion matrix, ROC-AUC]

# &#x20;   J --> M\[explain.py]

# &#x20;   M --> N\[SHAP global + per-flow<br/>feature importance]

# &#x20;   L --> O\[app/dashboard.py]

# &#x20;   N --> O

# &#x20;   O --> P\[Streamlit alert console]

# ```

# \## Background

# 

# CIC-IDS-2017 was generated by running DoS/DDoS tools, brute-force

# scripts, port scanners, and web exploits against a testbed and

# capturing the resulting flows with CICFlowMeter — the same tool used

# in many published IDS papers.

# 

# A few things shaped how this is built:

# 

# \* \*\*Class imbalance\*\*: \~80% of traffic is benign, and some attack

# classes (Heartbleed) have only a handful of flows. A model scoring

# 95% accuracy that never predicts "Heartbleed" is still useless in a

# SOC, so this project evaluates per-class recall and macro F1 instead

# of relying on overall accuracy.

# \* \*\*Data leakage\*\*: Source/Destination IP and timestamps are dropped

# deliberately. Leaving them in lets a model memorize which IP was the

# attacker in this specific 2017 capture instead of learning

# generalizable traffic behavior.

# \* \*\*Explainability\*\*: SHAP is used to show why a flow was flagged —

# useful for deciding whether to block or dismiss an alert.

#

# \## 1. Get the data

# 

# Download the CIC-IDS-2017 CSVs — 8 files covering Monday through

# Friday of the capture (e.g. `Monday-WorkingHours.pcap\_ISCX.csv`,

# `Tuesday-WorkingHours.pcap\_ISCX.csv`,

# `Wednesday-workingHours.pcap\_ISCX.csv`,

# `Thursday-\*-WebAttacks.pcap\_ISCX.csv`,

# `Thursday-\*-Infilteration.pcap\_ISCX.csv`,

# `Friday-\*-DDos.pcap\_ISCX.csv`, `Friday-\*-PortScan.pcap\_ISCX.csv`,

# `Friday-WorkingHours.pcap\_ISCX.csv`). Put all of them, unzipped, into

# `data/raw/`. Combined they're about 2.8M rows / \~1GB.

# 

# \## 2. Preprocess

# 

# ```bash

# python src/preprocess.py --raw\_dir data/raw --out data/processed/cicids2017\_clean.parquet

# ```

# 

# Prints the class distribution as it runs, which is the clearest way to

# see the imbalance problem.

# 

# \## 3. Train

# 

# ```bash

# \# Multiclass (which attack?) with Random Forest

# python src/train.py --data data/processed/cicids2017\_clean.parquet --target multiclass --model rf

# 

# \# Or XGBoost, or a binary BENIGN-vs-ATTACK model

# python src/train.py --target multiclass --model xgb

# python src/train.py --target binary --model rf

# ```

# 

# \## 4. Evaluate

# 

# ```bash

# python src/evaluate.py --model models/rf\_multiclass.joblib --test\_split models/rf\_multiclass\_test\_split.joblib

# ```

# 

# Look at recall per attack class, not overall accuracy — that's what

# tells you what the model would actually miss in production.

# 

# \## 5. Explain

# 

# ```bash

# python src/explain.py --model models/rf\_multiclass.joblib --test\_split models/rf\_multiclass\_test\_split.joblib

# ```

# 

# Generates a global feature-importance plot — usually flow duration,

# packet length stats, and flow bytes/packets per second come out on

# top.

# 

# \## 6. Run the dashboard

# 

# ```bash

# streamlit run app/dashboard.py

# ```

# 

# Step through individual test flows and see the prediction, a severity

# rating, and the top SHAP-driven features behind it.

# \## Possible extensions

# 

# \* \*\*Adversarial robustness\*\*: perturb a few flow features slightly

# (e.g. pad packet sizes, slow down timing) and check whether a DoS

# flow can be pushed across the decision boundary into BENIGN — related

# to evasion techniques used against ML-based IDS in practice.

# \* \*\*Concept drift\*\*: train only on Monday-Thursday, test on Friday's

# attack types the model never saw during training, to see how a

# static model degrades over time.

# \* \*\*Real-time capture\*\*: swap the static CSVs for live traffic via

# CICFlowMeter or `pyshark`, feeding flows into the trained model as

# they're captured.

# \* \*\*Feature selection\*\*: correlation/SHAP-driven pruning of the \~78

# raw features down to a smaller set, trading detection accuracy for

# lower compute cost on resource-constrained network appliances.

# 

# \## Notes on evaluation

# 

# \* Accuracy is misleading here — predicting BENIGN for everything would

# already score \~80% accuracy while catching zero attacks. Per-class

# recall and macro F1 are used instead.

# \* Dropping Source/Destination IP and timestamps avoids letting the

# model memorize which IP was the attacker in this specific capture.

# \* SHAP turns each prediction into a set of feature contributions

# rather than a black-box label.

# \* Offline evaluation numbers don't capture false positive fatigue,

# concept drift, or adversarial evasion in production.
